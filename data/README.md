# Demo data

Loaded by `uv run ingovo-search-seed` (see the main README).

## `synthetic_listings.json`

1,800 synthetic property listings (1,335 in Budapest, the rest across 15 other Hungarian
cities), generated by the scripts in `eval/synthetic/`. No listing is real:

- **Addresses and coordinates** are real building addresses sampled from
  OpenStreetMap through the Overpass API (`eval/synthetic/extract_osm.py`), so the
  listings sit on real streets. They do not describe the buildings at those addresses.
- **Prices** are sampled from per-district price-per-m² ranges (`price_sampler.py`).
- **Descriptions** come in three quality tiers on purpose (`describe.py`): `great`
  (written by Gemini), `templated` and `skeletal`, plus deliberately broken rows
  (`bad_case`) and rows with one field nulled (`nulled_field`). The mix lets the evals
  measure how ranking copes with thin or missing data.

The listings contain no agent, agency or contact information.

## `osm_pois_2026-07-13.json`

15,376 points of interest (schools, kindergartens, metro, tram and bus stops,
supermarkets, pharmacies, parks, hospitals and playgrounds) in Budapest and
six regional cities, extracted from OpenStreetMap on 2026-07-13. The seed loads them
into the `poi` table and precomputes each listing's distance to the nearest point per
category, which the parser's "near a metro / school" requests are scored against.
