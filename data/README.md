# Demo data

Loaded by `uv run ingovo-search-seed` (see the main README).

## `synthetic_listings.json`

1,800 synthetic property listings (1,335 in Budapest, the rest across 15 other Hungarian
cities), generated by the scripts in `eval/synthetic/`. No listing is real:

- **Addresses and coordinates**: each listing takes a real building address sampled
  from OpenStreetMap through the Overpass API (`eval/synthetic/extract_osm.py`) and
  keeps only its street: the house number is dropped, so a listing names a street,
  never a building. The coordinates are kept, because the proximity scoring needs
  them, and they are the coordinates of that OSM address point.
- **Property type**: `property_type` is the label the parser and the SQL filter use
  (`Lakás` or `Ház`); the building type (`panel`, `tegla`, `csaladi_haz`, `sorhaz`,
  `uj_epitesu`) is kept in `features.build_type`.
- **Prices** are sampled from per-district price-per-m² ranges (`price_sampler.py`).
- **Descriptions** come in three quality tiers on purpose (`describe.py`), all local
  templates with no model involved: `great` (three sentences), `templated` and
  `skeletal`, plus deliberately broken rows (`bad_case`) and rows with one field
  nulled (`nulled_field`). The mix lets the evals measure how ranking copes with thin
  or missing data.
- **Sale only**: every listing is for sale, so a rental search finds nothing.

The listings contain no agent, agency or contact information.

## `osm_pois_2026-07-13.json`

15,376 points of interest (schools, kindergartens, metro, tram and bus stops,
supermarkets, pharmacies, parks, hospitals and playgrounds) in Budapest and
six regional cities, extracted from OpenStreetMap on 2026-07-13 with
`scripts/extract_osm_pois.py`: one Overpass query per category and city, for example
`node["amenity"="school"]` and `way["amenity"="school"]` inside
`area["name"="Budapest"]["boundary"="administrative"]`, with ways and relations reduced
to their centre point. The seed loads them into the `poi` table and precomputes each
listing's distance to the nearest point per category, which the parser's "near a
metro / school" requests are scored against.
